## Critical

- [x] **A chain or bus keeps a raw pointer to a closed `Plugin` or `PluginChain` (use-after-free).** Fixed 2026-09-25; see CHANGELOG. Original note: `PluginChain` holds `MH_Plugin*` and `PluginBus` holds `MH_PluginChain*` (`_core.cpp` wrappers); `Plugin.close()` and `PluginChain.close()` free the native object regardless, since the Python-side reference keeps only the wrapper alive. Confirmed: `c = PluginChain([p]); p.close(); q = Plugin(FX); q.set_param(0, 0.25); c.process(...)` outputs 0.25 -- the chain processes through `q`, which reused the freed allocation. `chain.latency_samples` and `chain.reset()` also read freed memory. The same holds for `PluginGraph` (close the plugin, then `render_block`), `PluginBus` (close a branch chain or its plugin, then `process` or `latency_samples`) and a running `AudioDevice` over a plugin or chain -- all exit 139 under Guard Malloc (`DYLD_INSERT_LIBRARIES=/usr/lib/libgmalloc.dylib`). Fix: make `close()` raise while a chain, bus, graph or device still references the object, or refcount the native handle. Repro scripts: `build/audit-chain-bus/uaf_reuse.py`, `build/audit-lifecycle/container_uaf.py <case>`, `dev_close.py`.

- [x] **`close()` from another thread during processing crashes.** Fixed 2026-09-25; see CHANGELOG. Original note: Chain, bus and graph `process*` / `render_block` release the GIL, and nothing stops another Python thread from calling `close()` (or `Plugin.close()`, or `add_branch()`, which reallocates `branch_ptrs`) mid-call. Confirmed under Guard Malloc: `build/audit-lifecycle/race2.py chain 100` and 1 of 3 `race.py graph` runs exit 139. `Session.close()` against a concurrent `Session.open()` has the same shape (inferred; 70 attempts did not crash). Fix: a per-wrapper in-use count or shared mutex that `close` waits on; these are Python-level calls, not the RT path.

- [x] **A `MidiIn` callback that raises aborts the process.** Fixed 2026-09-25; see CHANGELOG. Original note: `midi_callback` (`_core.cpp`) lets `nb::python_error` escape on the libremidi thread: `libc++abi: terminating due to uncaught exception`, exit 134 (confirmed, `build/audit-lifecycle/midiin_raise.py`). This covers every `MidiIn` consumer, including `MidiMapper`'s `on_unmapped` and note callbacks (e.g. a forwarder calling `send_midi` on a 2-byte message). Catch in the trampoline and report through `PyErr_WriteUnraisable`.

- [x] **One UDP packet of nested OSC bundles crashes the process.** Fixed 2026-09-25; see CHANGELOG. Original note: Bundle parsing recurses without a depth limit, in JUCE (`juce_OSCReceiver.cpp` readBundle/readElement) and in `minihost_osc.cpp:55-63`. 2000 nested bundles (40 KB) overflow the socket thread's stack: exit 138 (confirmed, `build/audit-osc-midi/osc_nest.py 2000`; depth 1500 survives). Reachable from any sender that can reach an `OscServer` or `AudioDevice.connect_osc` port. Cap the depth (e.g. 8) before recursing; that means patching JUCE (`scripts/download_juce.py` already patches it) or owning the receive loop. Parse time also grows about quadratically with depth; the cap fixes both.

- [x] **Array shapes and frame counts are cast to `int` without a check.** Fixed 2026-09-25; see CHANGELOG. Original note: One cause, three confirmed failures (`build/audit-audio-io/`):
  - `AudioBuffer.from_numpy` (`_core.cpp:4251-4254`): a `(1, 2**31)` array crashes (exit 138); a `(1, 2**32+10)` array silently becomes `(1, 10)`. `np.zeros` is lazy, so this costs no memory to trigger.
  - `process*` bindings (`in_frames = (int) shape(1)`, `_core.cpp:899` and the other process, chain and graph variants): a `(2, 2**32+10)` input points channel 1 at channel 0's data; channel 1's result lands in `o[0, 10:20]`, no error (`t3.py trunc`).
  - `audio_resample` / `audio_read` build `MhAudioBuffer((int) ch, (int) frames)`, which becomes 0 frames, then `interleaved_to_planar` writes every frame into it: heap overflow, exit 138 after about 42 s for a resample to 2.25e9 frames (`_core.cpp:5351`, `:5251`; the `audio_read` path is inferred, same code).
  Fix: one helper that rejects any dimension above `INT_MAX` before the cast, used in every binding; cap frames in the C layer as well.

- [x] **`MidiFile` segfaults on an empty track or a bad track index.** Fixed 2026-09-25; see CHANGELOG. Original note: `duration_seconds` calls `back()` on an empty event list (`MidiFile.cpp:1470` via `_core.cpp`): `MidiFile().duration_seconds`, or loading a 14-byte type-1 file declaring 0 tracks, exits 139. `add_note_on` / `add_tempo` / the other `add_*` write out of bounds for a track index outside `[0, num_tracks)`, including -1: exit 139 (all confirmed). Return 0.0 for no events, and range-check `track`.

## High

- [x] **Chains drop MIDI past 256 events per block, silently.** Fixed 2026-09-25; see CHANGELOG. Original note: The chain's MIDI stage buffers hold 256 events (`minihost_chain.cpp:17`), on every path, whatever `midi_out_capacity` the caller passes; `mh_chain_process_auto` also hard-codes 256 as each chunk's capacity. Confirmed: 300 notes through `[fx]` with `midi_out_capacity=4096` return 256, and in `[fx, synth]` a note-on at event 300 never reaches the synth (silence). The bus inherits it and breaks its own contract: `midi_out_overflow` (`minihost_graph.h:135-138`, "never 0 when events were dropped") stays 0, because it tests only the caller's buffer (confirmed: 300 in, 256 out, `overflow=False`). Also, `autoChunkMidiIn.reserve(256)` followed by `push_back` allocates on the audio thread past 256 input events per chunk (inferred). Fix: size the stage buffers from a capacity fixed at chain creation, report a dropped count from `mh_chain_process_midi_io`, and OR it into the bus overflow flag.

- [x] **FLAC writes hang on silence (clang builds).** Fixed 2026-09-25; see CHANGELOG. Original note: Each exact-zero sample in the first block costs about 1.35 s: 4 zero samples at 16-bit take 5.5 s (confirmed), and a stereo render starting with 4096 silent frames would take about 3 hours. Vendored `tflac` uses its portable `tflac_wasted_bits` loop because clang reports `__GNUC__` 4.2, and on the first block `subframe_bitdepth` is still 0, so `--bits` wraps to `UINT_MAX` (`tflac.h:1359-1383`, `:1915-1928`; UBSan also flags a shift of 32 at `:1379`). `audio_write` holds the GIL throughout, so every Python thread stalls. GCC and MSVC builds use intrinsics and are unaffected. Fix: set `subframe_bitdepth` before the loop (patch tflac) or use `__builtin_ctzll` under `__clang__`; add a FLAC-silence test; release the GIL in `audio_write`.

- [x] **`AudioBuffer` DSP ops skip work after `clear()` if the data was written through a view.** Fixed 2026-09-25; see CHANGELOG. Original note: The ops wrap `juce::AudioBuffer`, whose `isClear` flag is set by `clear()` and reset only by its own write accessors, not by writes through `as_ndarray()`, `np.asarray`, DLPack or `channel_view`. After `a = b.as_ndarray(); b.clear(); a[:] = 1.0`: `magnitude()` and `get_rms_level()` return 0.0, `apply_gain` and `reverse` do nothing, and `add_from` adds nothing (confirmed, `t1.py`). `process_audio(normalize=...)` and render auto-tail use `magnitude()`. Reset the flag (touch `getWritePointer` on each channel) at the start of each op, or avoid the JUCE methods that consult it.

- [x] **OSC server threading.** Fixed 2026-09-25 (all three); see CHANGELOG. Original note: Two confirmed problems remain (`build/audit-osc-midi/`):

JUCE's `disconnect()` waits only 10 s, then `delete server` destroys the listener while the thread is still inside it (`minihost_osc.cpp:168-176`); exit 138 at 12 s (`osc_slowclose_p.py 12`). Wait until the thread has exited before freeing.

- [x] **OSC wildcard patterns backtrack exponentially.** Fixed 2026-09-25; see CHANGELOG. Original note: A 32-byte address `"/mh/param/" + "*"*12 + "Q"` stalls `OscMapper` for 4.14 s with four bound parameters; 13 stars against a 21-character slug take 4.46 s per binding, growing roughly as C(n+k, k) (confirmed, `osc_redos2.py`; JUCE `OSCPatternMatcherImpl::matchAnyOrNoChars` via `control.py`). - [x] **Callback dispatch loses or duplicates events.** Fixed 2026-09-25; see CHANGELOG. It stays in bounds only because the buffer reserves 1024; past that a reallocation would be a use-after-free (inferred). That is exactly what Phase 6 worked around: a parameter past the 128th has no CC to bind, `each` could not conditionally omit a message, so `touch.py::_branch_table` doubles every widget kind into a `...NoCc` twin. Six complete templates for two independent questions; schema 3 nests them and makes it five, and the growth is additive rather than multiplicative (a third question: seven against twelve). py2tosc's own schema-3 fixture is this case verbatim and its changelog names minihost as the caller that prompted the change.

  **Blocked on a release.** py2tosc's working tree has `SCHEMA = 3` but `__version__` is still `0.5.2` and that is the newest tag, so emitting schema 3 now would produce descriptions that `pip install 'minihost[touch]'` refuses with a `SchemaError`. When it lands: move the `touch` extra floor and `CIBW_TEST_REQUIRES` off `>=0.5.2`, re-copy `tests/check_json.py` (the vendored one is from 0.5.2 and does not know schema 3), and simplify the branch table. `build_layout` already stamps what `required_schema` computes rather than a constant, so the envelope needs no change. Rows could also drop the `cc` key entirely instead of carrying a sentinel, since only the taken branch is substituted into. Full notes in [docs/dev/osc_and_touch.md](docs/dev/osc_and_touch.md) section 6.

The WinMM and ALSA macros mirror libremidi's own cmake but have **never been built or exercised** -- only macOS/CoreMIDI is verified. Neither platform has the run-loop hazard that drove the isolation work there, so behaviour may differ. Highest-value open item: a whole subsystem is unproven on two of three platforms.

- [ ] **`mh_process_sidechain` has no MIDI input** (review, from H6). - [ ] **`save_vstpreset` class-id auto-detection needs VST3 SDK 3.7.5+** (review, from H2). - [ ] **Callbacks require manual `poll_callbacks()` and are easy to miss** (review M2). `set_change_callback` / `set_param_value_callback` / `set_param_gesture_callback` only enqueue; nothing fires until polled (`_core.cpp`). The no-GIL-on-the-audio-thread rationale is sound, but a user who registers a callback and never polls sees total silence with no diagnostic, and `callback_events_dropped()` only becomes non-zero after 1024 undelivered events. - [ ] **Device MIDI is quantised to the block boundary** (review M4). `minihost_audio.c` and `live.cpp` set `sample_offset = 0` for every incoming event, discarding libremidi's timestamps. - [ ] **No SysEx support anywhere** (review M5). `MH_MidiEvent` is a fixed `(offset, status, data1, data2)`, so there is no SysEx path in the C API, bindings, graph or device layer (`live.cpp` explicitly drops anything longer than 3 bytes). - [ ] **Resampling is linear-interpolation only** (review M6). `minihost_audiofile.c` uses `ma_resample_algorithm_linear`; that is the only algorithm miniaudio ships, and its one quality knob (the anti-alias filter order) is now at the maximum, so the remaining aliasing and HF loss are inherent to linear interpolation. It is on by default in `process_audio_to_file` (`resample_to_plugin_rate=True`), so processing a 44.1 kHz file through a 48 kHz plugin silently degrades the audio. A real fix means a second backend (sinc/polyphase) behind a quality argument. At minimum document it.

Original note: They are on the top-level parser, so `minihost process plugin.vst3 --block-size 1024 ...` fails with "unrecognized arguments", and `minihost process --help` never mentions them -- yet the command prints `Block size:` in its summary. Additionally `-r/--sample-rate` is silently overridden by the input file's rate whenever audio input is present, so it only matters in MIDI-only mode. - [x] **Sample-accurate automation takes locks on the audio thread** (review M7). Verified fixed 2026-09-25: `mh_process_auto` and `mh_chain_process_auto` both call `mh_set_param_rt`. Original note: `minihost.h` declares the `mh_process*` family "no locks, no allocations after warmup", but `mh_process_auto` calls `setValueNotifyingHost` (which dispatches to listeners, and minihost's own then takes a mutex) and `mh_chain_process_auto` calls `mh_set_param` (which takes `stateMutex` outright). - [x] **Audio-thread MIDI output blocks; the out-ring is dead code** (review M3). Verified fixed 2026-09-25: the callback pushes into `midi_out_buffer` and a pump thread sends; `mh_midi_out_send` is not called on the audio thread. Original note: `minihost_audio.c` calls `mh_midi_out_send` -> libremidi directly from the miniaudio callback, once per event -- a syscall-bearing, potentially allocating call on the RT thread. Meanwhile `dev->midi_out_buffer` is created and freed but never used: the ring buffer that exists precisely to avoid this is dead.

- [ ] **`send_midi`'s ring is single-producer** (review, from H11). It no longer shares the libremidi input thread's ring, but its own is SPSC too, so concurrent `send_midi` from several threads would reintroduce the same corruption. The single-thread contract is documented in `minihost_audio.h` and the binding; make it MPSC if multi-thread sending ever becomes a supported pattern.

- [x] **`mh_graph_get_midi_output_events` over-reports the event count** (review M11). Fixed 2026-09-24 (C ABI 2.9.0): the count is now what the node holds, and `mh_graph_get_midi_output_dropped` reports losses. Original note: It sets `*num_events_out` to the *untruncated* total but copies only `min(total, capacity)`. The Python wrapper uses that number both to size the buffer and to `resize()` afterwards, so a block producing more than 1024 events yields fabricated zero-filled tuples in the tail. Return the copied count and expose the truncated total separately -- the node already tracks both.

- [x] **`plugincache` discovers formats minihost cannot load** (review M13). Verified fixed 2026-09-25: `PLUGIN_EXTS` is VST3, LV2 and (macOS) AU only, and bundles are fingerprinted by their contents. Original note: `PLUGIN_EXTS` includes `.dll`, `.so`, `.clap` and `.vst`; minihost supports VST3, AU and LV2 only. On Linux a scan of any directory containing shared objects probes every one and caches a permanent error entry. Also `_fingerprint` stats the bundle *directory*, so replacing the binary inside a macOS `.vst3` in place does not change the mtime and stale metadata is served indefinitely.

- [x] **Redundant state serialisations** (review M14). Fixed 2026-09-25: `mh_get_state_size` keeps its snapshot for the next `mh_get_state`; see CHANGELOG. Original note: `Plugin.get_state` calls `mh_get_state_size` then `mh_get_state`, each serialising the whole state -- two full dumps (megabytes, sometimes seconds) per save, and a hazard if anything mutates the plugin in between. The H2 fix added another snapshot on the `set_state` side, which is the price of being able to report failure at all. A `mh_get_state_alloc` (or caching the `MemoryBlock` behind the size query) would pay off on both paths.

- [x] **MIDI open failures discard libremidi's returned error** (review, from M12). Fixed 2026-09-25: the returned error is appended; see CHANGELOG. Not covered by a test: making libremidi fail to open a real port needs an OS-level fault. Original note: Thrown `stdx::error`s now report properly via `describe_current_exception`, but the *returned* error from `open_port` / `open_virtual_port` is still swallowed in favour of a fixed string. Feeding it through the same helper would finish the job.

- [x] **`Plugin`'s move constructor leaves a stale trampoline pointer** (review L2). Fixed 2026-09-25: moves are deleted on `Plugin`, `PluginChain` and `AudioDevice`. Original note: It moves `plugin_` / `sample_rate_` / `max_block_size_` but not `non_realtime_`, the callback holders or the callback queue -- and the C-layer trampolines were registered with the old `this`. Not reachable from Python today (nanobind holds `Plugin` by pointer) but a live trap for anyone extending the class. Fix the move or `= delete` it, as the copy constructor already is.

- [x] **`mh_message_thread_init` cannot restart after shutdown** (review L3). Verified addressed 2026-09-25: shutdown is documented as final, and a shared mutex serialises `run()` against shutdown. Original note: `std::call_once` means a second `init` after `mh_message_thread_shutdown` silently does nothing, so every thread-affine operation reverts to running inline. A foot-gun for a library embedded in a longer-lived host. There is also a small race: `shutdown` clears `enabled_` before joining, so a concurrent `run()` executes inline while the thread is still alive.

- [ ] **Audio-thread diagnostics in the desktop app** (review L6). `live.cpp` scans every output buffer for a non-zero sample on *every* callback, and keeps doing so for as long as the project is silent; `fprintf` on the audio thread is acknowledged in comments but still an RT violation. Move both behind a lock-free flag consumed by the GUI timer.

- [x] **Uninitialised pointer array passed as non-null** (review L7). Verified fixed 2026-09-25: `in_table` defaults to `nullptr` and is set only when the node has inputs. Original note: `minihost_graph_v2.cpp` leaves `const float* in_ptrs[64]` uninitialised when a node has no input ports, then passes it to `mh_process*`, which branches on `if (inputs)` -- true for a stack array. Safe today only because such nodes always have zero input channels, so the copy loop never runs. The comment claims it passes null, which it does not. Pass `nullptr` explicitly.

- [x] **Seqlock payload is a non-atomic struct copy** (review L11). Verified fixed 2026-09-25: `TransportSeqlock` stores every field as its own atomic. Original note: `MH_PlayHead::read`/`write` copy `State` while the writer may be mid-write. The sequence counter makes the result correct on retry, but the copy is a formal data race (UB, and TSan will flag it). Practically fine on the target architectures; worth a comment or relaxed atomic fields.
